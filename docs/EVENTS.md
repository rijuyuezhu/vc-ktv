# 场次与数据

每场 KTV 只有一个活动场次；用户、队列、演唱统计、媒体文件和本场管理员全部独立。默认数据目录：

```text
~/.local/share/vc-ktv/
  active-session
  sessions/<event-id>/
    info.json
    room.sqlite3
    media/
```

管理员在「设置 → 场次管理」创建或结束场次；结束后数据库及媒体归档，不自动删除。本场用户账号下一场不能继续使用。全局管理员可以创建场次及管理本场管理员账号，本场管理员仅能操作当前场次。历史场次及 CSV 导出位于「设置 → 历史歌单」。普通用户可以在进行中的场次查看已唱歌单并下载仍保留的视频，不能访问其他场次文件。

## 本场设置

点歌顺序、允许无字幕、清晰度、字幕风格、在线播放带宽预算及电视 HTML 字幕模式保存在本场 SQLite。保存后不用重启，具体生效时间见 [AUTOPREP.md](AUTOPREP.md)。公平轮播按每人有效已唱首数调度，只有领取普通歌曲时才把长期落后的可播用户虚拟进度补到最多相差两首；注册、页面刷新与等待都不产生欠账。真实演唱统计独立，管理员置顶/重唱不计用户轮次；先来先唱不使用此调度。

## 归档与旧版数据

历史 CSV 包含点歌记录及播放状态，导出为只读操作。旧版直接存放于根目录的 `room.sqlite3`、`media/` 不会在启动时自动迁移，需要确认无在途任务后才考虑使用 `scripts/archive_legacy.py`。关闭活动场次时若仍有歌曲正在播放或制作，服务会拒绝关闭，避免跨场次任务和文件冲突。

生产备份应使用 SQLite 在线备份，而不是在服务运行中直接复制数据库文件；私密数据库和媒体不应上传到 GitHub。
