# 来源逐句 LRC 快速字幕（#110）

## 使用与安全边界

默认仍是完整 **Kim → 双遍 Qwen3-ASR → TIFA → ASS/MP4** 对齐。歌词候选来自 VCPedia、网易云音乐、LRCLIB 等独立来源；只在候选的 LRC 包含严格递增的逐行时间、所有已清理的演唱歌词行都有时间、没有不明来源 `offset`/额外无时间行时，显示「**可选：沿用来源逐句时间轴**」。LRCLIB 有 `syncedLyrics` 时优先使用，只有 `plainLyrics` 时不显示此选项。YRC/来源原生逐字时间戳暂不支持；可将每句有效显示区间均分给每个字制作**估算的逐字渐变**，但绝不声称它与真实歌声逐字对齐。

网易云歌词现在会先打开**逐行校正对话框**：展示保留制作信息在内的原始歌词行，沿用已有的开头制作信息清理规则预选需要保留的行（标黄）；未选择的行保持普通颜色，用户可逐行切换，至少保留两行。服务端通过原歌词的签名及行号重建选择，不接受客户端任意改写。选择“重新对齐”时只保留选中的文字；选择“沿用来源时间轴”时，将原始来源逐句时间戳按原行序映射到所选行（包括重复歌词），原有音源偏移仍有效；如果某个保留行没有来源时间戳，需要换用普通歌词对齐。其他歌词来源的选择流程不变。

用户需要明确选择这一模式，预览来源行时间和歌词，并以**秒**设置 -60 到 +60 的偏移（正数：视频演唱比提供的歌词时间晚）。服务端只接受同一个场次、歌曲、来源和候选签名绑定的源文本与时间轴，再次检查原始文本和清理后的歌词一致、偏移后每行开始时间落在视频内且严格递增。失败会返回可解释的错误，用户可以切回默认模型对齐；不自动偷偷采用或返回来源计时。

这种直接使用来源时间轴的方法**只适合与来源音源完全一致的歌曲，不适合演唱会、翻唱或改编版本**。此校验**不能判断歌曲是否为同一录音、翻唱版本或剪辑 MV**。即使时长与所有时间戳合法，如果错版、变速、长前奏不同，仍可能整首对不上。用户需要依据 BV 和来源版本自行判断并可调整偏移。歌词详情显示当前模式和偏移；管理员重唱保留来源模式信息。普通用户直接选择其它歌词、上传或选择原片时会重置此模式，防止无效时间戳沿用到修改后的歌词。

## 渲染与可复现

数据库将 `lyric_choice`（最终显示歌词）、`source_lrc_raw`（原始来源全文）、`provider_lrc`（规范化的逐句时间轴）、`lyric_timing_mode` 和 `lyric_offset_ms` 分开存档。准备任务使用同一套事件数据库任务领取、取消和原片保留逻辑，唯一区别是用户确认的源时间轴直接变成行级 `Timeline`，每行显示区间（最多 8 秒，避免长间奏拖尾）按**文字字符数平均划分**为 `estimated` 的 `Unit`，使用已有上游 `write_bundle` 生成符合本场字幕预设的 ASS/LRC；共用 FFmpeg/H.264、原音轨保持、可选紧凑编码和视频限码率，之后仍得到可下载 MP4。没有额外模型调用，不改变缺省字幕流水线。

每次制作保留单独的 `source-provider.lrc`、`confirmed_lyrics.txt`、`aligned.lrc`、`provider_timing.json`、`provider_subtitles/` 与 `attempt.json`。标明 `character_timing=equal_split_estimate` 和“来源时间尚未音频声学验证”，不能将估算的逐字渐变表示为 TIFA 原生词时间。原片在异常时不被覆盖；如已经开始播放，不会热替换视频。

## 2026-11-01 实测与版本差异

Spark-WSL 对历史场次第 94 首《monologue》进行只读取样和独立输出：公开网易云检索的几份同名候选与原 BV 的已确认歌词相比，文本相似度约 0.833、0.930、0.959，但均**不是完全一致**；甚至不相干的同名歌曲也可有时间戳在该视频时长之内。仅凭“有时间戳”和“未超长”不能认定来源与 BV 对齐。这也是为什么**必须 opt-in**。

在该歌曲原片截取 60.01 秒，采用来源《Monologue (X Studio Cover)》的前 7 行歌词、明确设置 **+2 秒偏移**，不调用 GPU 模型，在实际 FFmpeg 中约 **7.06 秒**得到 26.1 MB MP4；音频逐流 MD5 与截取原片完全相同。这是来源时间轴的**可渲染性与开销**测量，不是音频对齐准确性证明，也不能直接和历史 257 秒整首歌的 Kim+Qwen+TIFA 运行时间作等量加速比。实际用户选择错版时只能保证合法渲染，不能保证唱词吻合。
