# 本地原片 + HTML 卡拉 OK 字幕（#131）

管理员在本场设置中开启「电视播放本地原片，叠加实时卡拉 OK 字幕」后，独立电视播放页优先选已下载并保留的本地原片（绝不直连 B 站 CDN），同时载入本次字幕尝试的 `timeline.json`、`display_plan.json`、`style.json`。这些文件来自现有 ASS 烧录流程，不新增声学对齐或独立时间轴。浏览器通过当前播放 `<video>.currentTime` 渲染双行歌词、按 `Unit` 时间逐字扫色；字号、字体、位置、单双行、描边宽度、白色底字和高亮色均来自当前歌曲打包的 `style.json`（即制作时管理员选择的预设）。实时字幕使用两层文字：底层是黑色描边阴影，顶层是白色底字及黄色渐变，以免黑色阴影覆盖透明渐变。其字体、描边和双行位置按 ASS 的 1280×720 虚拟坐标相对视频画面缩放，而非相对整个浏览器窗口；浏览器不会实时重新制作 ASS。已经做好的歌曲仍沿用制作时的样式，新选择的管理员样式对后续开始准备的歌曲生效。为使 HTML 字体大小与 libass 烧录版相符，HTML 使用统一的 `ASS_FONT_TO_CSS=0.69` 缩放，并按 CSS 字号的 `0.075` 调整底部锚点（再按实际视频画面缩放）；不更改 ASS 预设及已生成文件。在同一份真实时间轴、1280×720、22.8 秒画面中，经典双行、大屏高对比和简洁单行的 HTML 与 ASS 文字范围（水平及垂直）相差最多 2 像素。其他字体及浏览器系统可能存在少量差别。

控制面板仅在 HTML 模式可用时显示字幕偏移，支持 `-5s`、`-1s`、`-0.1s`、`+0.1s`、`+1s`、`+5s`。正数令字幕比视频晚显示，负数令字幕提前；每首新歌自动归零。暂停、重唱、跳过与下一首预加载仍由原电视播放队列负责。

场次管理员另可设置 **在线播放带宽预算（1–12 Mbps，默认 3）**；该设置取代 `VC_KTV_VIDEO_MAXRATE_KBPS` 环境变量以及原「30 MB 二次压缩」开关。下一次字幕制作时，烧录成片采用一次 H.264 编码，将视频峰值预算设置为 `round(Mbps × 1000) - 384` kbps，给原音轨及封装预留余量。无论选择哪一种电视播放模式，**下载链接始终指向原来的烧录字幕 MP4**，原片文件不覆盖、不删除。码率设置影响未来制作，不会修改历史视频。

如果启用了原片播放且原片平均文件码率超过所设预算的 80%，字幕完成后会从**原片**编码一份 `tv-source.mp4` 缓存，使用与烧录版相同的 H.264 CRF / VBV 策略并复制音轨；保持原分辨率和音频。此缓存与字幕数据都绑定到该歌曲这次成功的准备尝试，并通过有过期签名的 TV 媒体与字幕地址访问。缓存不存在、压缩失败、旧缓存比当前预算宽松、无可靠字幕时间轴或播放端加载失败时，自动回退烧录版。没有服务端媒体处理发生在 TV 的 HTTP 请求路径。

该配置**不强制将总媒体峰值限制为固定 3 Mbps**：VBV 约束视频码率，复制的音轨自身可能超出预留，浏览器缓冲和网络共享也会带来波动。大幅降低带宽预算会增加视频压缩损失。原片码率以文件字节数和歌曲时长估算，瞬时峰值不等于平均值。旧的已烧录歌曲如果缺乏配套高码率缓存，将继续使用烧录版，不会阻塞直播时即时转码。
