# 自动点歌与歌词制作流水线

文档描述 #29 的新 AutoPrep 自动制作链路；历史验收记录见 [VALIDATION.md](VALIDATION.md)，上游版本固定信息见 [UPSTREAM_PIPELINE.md](UPSTREAM_PIPELINE.md)。**生产服务升级须单独批准。**

## 用户与管理员的边界

普通用户：输入 BV 号 → 等待自动搜索 → 从候选列表选歌词，或者自行输入关键词搜索 → 返回点歌大厅。多个用户可以并行点歌，歌词选择只对原点歌者开放。用户不选歌词时保留原片，但默认字幕门槛会暂缓播放；管理员可选择允许无字幕播放。

管理员：登录并打开 TV 播放页，首次点击播放后自动切歌。用户选词、模型下载和字幕审核都不交给管理员。TV 目前采用浏览器或屏幕镜像，尚未接入原生乐播 SDK。

## 准备流程与回退策略

1. 提交 BV 时向 B 站公开接口查询视频标题、分 P 和时长，写入 SQLite，立即返回歌曲 ID。
2. 后台单线程按请求顺序下载原片，默认 **720p**（可在管理员设置中选择 **480p**），失败会尝试更低清晰度。首选 yt-dlp；若失败则尝试 B 站公开 view/playurl，选择不高于设定的 H.264/AAC DASH/MP4 并用 FFmpeg 无损封装。不能绕过 B 站账号权限；文件可能原本就只有低于设置上限的清晰度。公开视频下载失败后有限次重试（60/300 秒），不阻塞其他歌曲。设置只对之后开始下载的歌曲生效。
3. 视频完成 FFprobe 校验即进入 Ready；是否可进入 TV 队列由本场字幕门槛决定。字幕烧录成片默认只执行一次 H.264 CRF 23 编码，**不限制文件大小**（保留原分辨率和原可复制音轨）。管理员可在本场设置中勾选“二次压缩成片至约 30 MB”，仅开启后、首次成片超过 30 MB 时才重新从原视频和 ASS 烧录，目标约 28 MB（保留 H.264 和原可复制音轨）。30 MB 只是 best effort，不保证极长歌曲或大音轨可达标；二次编码失败仍保留首遍可播放成片。**开关在字幕制作任务开始时读取**，保存后无需重启，后续开始制作的歌曲自动生效，已开始制作和已生成的成片不改变。
4. 前端根据标题提取歌名，先查 VCPedia 与 LRCLIB；候选不足或来源单一时尝试中日文字形、网易云音乐原文 LRC、UtaTen 与 J-Lyric 的固定来源正文，最多展示 6 条且优先覆盖不同来源。用户可自行编辑搜索词；不自动选择候选。
5. 点歌者选择候选后，后台在领取字幕任务时读取本场的字幕样式预设快照，使用已确认歌词运行上游完整流程：音频提取 → Kim 分离推理人声 → 双遍 Qwen3-ASR 找位置 → TIFA 安全分块/局部恢复 → 标注原生或估算时间 → ASS/LRC → MP4。歌词显示始终使用原文，成片保留原视频音轨；失败保留当前尝试日志与原片。
6. 只有歌曲仍为 Ready 且原片未改变时，才切换成带字幕成片；如果已经开始播放，则保留正在播放的原视频，不中途换流。
7. 未选歌词、歌词未搜到、TIFA 无法处理、转码失败时保留原视频文件，但默认不允许无字幕播放。管理员可在高级队列操作中仅重试失败字幕，或对已经完成但尚未播放的歌曲主动“按新风格重制”；不重新下载原视频，重制失败保留原有成片。每次尝试的日志和选定预设单独归档。

## 状态说明

- pending / downloading：原视频等待下载或下载中。
- unavailable：媒体暂无法取得，显示原因与重试次数；其他歌曲照常进行。
- downloaded：原片已就绪，尚未选择歌词或等待字幕处理。
- aligning：已选歌词，正在运行 Kim/Qwen3-ASR/TIFA/FFmpeg 制作；除非管理员允许无字幕，原片不可播。
- done：字幕成片已制作，尚未开始播放时可切换到成片。
- original：字幕生成失败，保留原片及诊断，默认不可播；可重试字幕。
- manual：管理员通过高级功能主动上传素材。

Ready/playing/played/skipped 是独立于准备阶段的播放状态；只有 Ready 才能进入公平可播队列。数据库和媒体都保存在 VC_KTV_DATA 下（默认 ~/.local/share/vc-ktv）。

## 验证范围与限制

- 在 Spark-WSL ARM64 CUDA 上，已验证实际 Kim → Qwen3-ASR → TIFA → ASS/MP4：4.73 秒 ACE-KiSing 歌声、逐字模型时间戳、原始音轨 AAC 数据一致。见 [SPARK_WSL_PIPELINE.md](SPARK_WSL_PIPELINE.md)。
- 针对一个公开测试视频，yt-dlp 页面解析失败后，公开 API 备用下载成功并生成 H.264/AAC MP4。
- 在隔离场次测试了访客点歌 → 选词 → AutoPrep → 真实模型 → done → TV next → 媒体端点 200；原音轨 MD5 一致。这里使用本地许可素材代替实际 B 站下载。CI 覆盖选词授权、后台任务、失败回退、字幕重试、场次隔离和上游算法边界；真实长歌和乐播设备仍需另验。
- 对齐的时间戳只是 best effort：相同歌词文本也可能与翻唱录音有不同的速度、跳句或乐器间奏；不能据此宣称准确率达标。

## 来源与媒体权利

VCPedia、LRCLIB 与 B 站各有独立的访问及版权条件。可获取内容不等于可以公开再分发。TIFA、Kim、Qwen3-ASR 均使用本地模型，权重不放入 Git。处理流水线已从 [AutoASSrenderer4karaOK](https://github.com/Volta233/AutoASSrenderer4karaOK) 复制/适配，原作者许可见 [third_party/autoassrenderer](../third_party/autoassrenderer/README.md)，各模型另有独立条款；未复制上游的 GUI、Windows 安装器或数据库。

### 歌词候选响应优先级

普通访客打开选词弹窗时，搜索框立即填入从已提交歌曲标题提取的歌名，便于人工纠错。VCPedia 与 LRCLIB 各自独立查询：**先返回的候选立即显示且可直接选定**，不等待另一个来源。慢速的其他来源只在用户点击「更多歌词来源」时访问；已选歌词后立即终止前端等待，并忽略旧搜索结果。签名候选、单曲归属和频率限制仍在后端执行；页面不会自动决定歌词版本。

### 管理员对单曲的处理

除了整场允许无字幕播放外，管理员还可对某首**已有原视频且尚未播放**的歌曲选择「原片入队」。这会为该歌曲设置专用豁免，不改变其他歌曲的字幕门槛；如果字幕计算已经开始，最终结果不会覆盖原视频，但 GPU 子进程**不会被瞬时终止**。管理员可以之后点击「重新生成字幕」，取消单曲豁免并重新进入字幕流水线。

管理员可以取消正在等待、已下载、对齐中、手工渲染中的歌曲；取消后仍可能有旧的计算收尾，但不会重新进入待播放队列。正在播放或已经唱完的歌曲必须通过播放控制结束，不允许覆盖正在播放的媒体。

管理员列表显示下载、提取音频、Kim 分离、Qwen/TIFA 对齐、ASS、FFmpeg 烧录的实际阶段与阶段已用时。阶段仅在流水线切换时写入数据库，不读取 GPU utilization 或生成虚构百分比，不增加模型内部采样开销。

## 手机本地视频投屏

本场已登录成员和管理员可在歌单中查看媒体准备阶段，等待视频完成后点击「下载视频」。
下载走 `GET /api/songs/{id}/download`，直接以附件返回已有媒体，不启动新的推理或下载队列，
也不会改变公平轮播顺序。只有本场的 ready/playing 且成片已完成的歌曲允许下载；
字幕失败或管理员跳过字幕时，按钮明确标注「下载原片」。已播放完成、取消及过期场次的歌曲不能从该接口下载。
浏览器下载文件通常落到手机的「下载」目录，是否出现在相册由 Android 媒体索引决定；
用户可在乐播投屏的相册或本地视频中手动选择，暂不提供乐播自动续播。

## 统一队列：取消、重唱和手动投屏

- **普通用户取消**：仅已登录点歌者可取消自己的 waiting/ready/rendering 歌曲（包括下载中、模型制作中）；`POST /api/songs/{id}/cancel` 会立刻将记录设为 cancelled，现有计算可能仍会收尾，但不会重新排队。播放中不能取消。
- **管理员下一首重唱**：管理页「已唱歌曲」可选择本场已经 played 的歌曲。生成新的歌曲记录，保留原历史，使用独立硬链接复用已完成的原片与字幕成片，**不重新下载或推理**；新记录标记 priority_next，下一次领取时优先于公平/FCFS 正常队列，多首优先项按加入顺序执行。唱完后才再次计入用户统计。
- **手动投屏**：管理员在播放控制区将播放方式设为「手动投屏」。服务端保存该模式并拒绝 TV 浏览器端自动领取/结束歌曲。管理员点击领取下一首，将其标记为 playing；大按钮下载当前视频到手机后，从乐播相册/本地视频选择并播放。必须由管理员点击「唱完并切下一首」或「跳过并切下一首」来确认当前状态及领取下一首。**仅下载不改变播放状态，也不增加演唱次数**。
- 不能在歌曲 playing 时切换播放方式；切换前先唱完或跳过当前歌曲。普通用户仍通过同一份全局歌单观察当前歌曲、待播放和制作进度；不存在独立的下载/投屏队列。
- 文件保存位置和是否出现在相册由手机浏览器及 Android 媒体索引决定；此功能不依赖乐播 SDK，也不代表已实现自动投屏。

## 管理员分级与本场授权

全局管理员仍使用部署时配置的管理员密码登录（用户名留空），能够创建场次、查看所有历史场次及 CSV，管理本场管理员账号。每个活动场次可创建多个独立的**本场管理员**：全局管理员在管理页的「本场管理员账号」折叠区设置用户名和初始密码，本场管理员填写用户名及密码后使用同一个管理页面。

本场管理员可以操作当前场次的播放、歌曲、字幕、下载、设置及结束归档；仅能看到/导出**当前场次**的记录，不可创建新场次、访问旧场次 CSV 或管理其他管理员账号。场次结束，登录与由本场管理员创建的电视控制链接即失效；下个场次须重新创建账号。全局管理员可以在本场内重置密码或撤销账号，相关登录和电视链接立即失效。

本场管理员凭证以现有 scrypt 密码哈希存于该场次的 SQLite `event_admins` 表，绝不把密码哈希返回客户端。服务端每次验证管理员 Cookie 的签名、场次 ID、账号 ID 与凭证版本，并复查账号是否仍存在。现有全局管理员 Cookie 和历史 TV 控制链接在各自有效期内仍兼容；场次切换继续隔离媒体、普通用户及管理权限。
