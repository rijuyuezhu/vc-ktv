# 自动点歌与歌词制作流水线

文档对应 **v0.5.0**；旧版本的实际验收记录见 [VALIDATION.md](VALIDATION.md)。

## 用户与管理员的边界

普通用户：输入 BV 号 → 等待自动搜索 → 从候选列表选歌词，或者自行输入关键词搜索 → 返回点歌大厅。多个用户可以并行点歌，歌词选择只对原点歌者开放。用户不选歌词也能播放原片。

管理员：登录并打开 TV 播放页，首次点击播放后自动切歌。用户选词、模型下载和字幕审核都不交给管理员。TV 目前采用浏览器或屏幕镜像，尚未接入原生乐播 SDK。

## 准备流程与回退策略

1. 提交 BV 时向 B 站公开接口查询视频标题、分 P 和时长，写入 SQLite，立即返回歌曲 ID。
2. 后台单线程按请求顺序下载原片，首选 yt-dlp；若其网页解析失败，尝试 B 站公开 view/playurl、选择 H.264/AAC DASH/MP4 并用 FFmpeg 无损封装。公开媒体获取失败后有限次重试（60/300 秒），不阻塞其他歌曲。
3. 视频完成 FFprobe 校验即进入 Ready，可由 TV 页面播放。
4. 前端根据标题提取歌名，调用 VCPedia 搜索/正文提取及 LRCLIB 搜索，返回最多 6 条候选及全文。用户可自行编辑搜索词；不自动选择候选。
5. 点歌者选择候选后，后台读取已保存的歌词，检查本机 TIFA 模型环境。若可用，则从原片提取音频，运行本地 TIFA GPU 对齐，生成 TextGrid，再转换成增强 LRC 并烧录 ASS 字幕。少量 TIFA 无法识别的拉丁哼唱前缀会做确定性清理，原始歌词在对齐数据目录留档。
6. 只有歌曲仍为 Ready 且原片未改变时，才切换成带字幕成片；如果已经开始播放，则保留正在播放的原视频，不中途换流。
7. 未选歌词、歌词未搜到、TIFA 无法处理、转码失败时都保留可用的原视频。下载失败是唯一会阻止此歌曲 Ready 的情况。

## 状态说明

- pending / downloading：原视频等待下载或下载中。
- unavailable：媒体暂无法取得，显示原因与重试次数；其他歌曲照常进行。
- downloaded：原片已就绪，尚未选择歌词或等待字幕处理。
- aligning：已选歌词，正在运行可选 TIFA/FFmpeg 制作；原片仍可播。
- done：字幕成片已制作，尚未开始播放时可切换到成片。
- original：字幕生成失败，保留原片。
- manual：管理员通过高级功能主动上传素材。

Ready/playing/played/skipped 是独立于准备阶段的播放状态；只有 Ready 才能进入公平可播队列。数据库和媒体都保存在 VC_KTV_DATA 下（默认 ~/.local/share/vc-ktv）。

## 验证范围与限制

- 在一台 ARM64 Linux / NVIDIA GPU 测试主机上，已对公开授权样本验证下载、TIFA GPU 全曲推理及 MP4/ASS 生成。测试的是早期自动选词版本，不应视为 v0.5.0 用户选择流程的完整实机验收。
- 针对一个公开测试视频，yt-dlp 页面解析失败后，公开 API 备用下载成功并生成 H.264/AAC MP4。
- v0.5.0 新增的用户选词授权、后端任务触发与失败回退经过自动化测试；CI 不验证真实歌曲的声学时间精度或乐播设备。
- 对齐的时间戳只是 best effort：相同歌词文本也可能与翻唱录音有不同的速度、跳句或乐器间奏；不能据此宣称准确率达标。

## 来源与媒体权利

VCPedia、LRCLIB 与 B 站各有独立的访问及版权条件。可获取内容不等于可以公开再分发。TIFA 属本地机器学习模型，权重和额外运行环境不包含在 Git 仓库中。实现思路参考原作者已授权使用源码的 [AutoASSrenderer4karaOK](https://github.com/Volta233/AutoASSrenderer4karaOK)，但本项目未复制整套 Windows GUI、Kim 分离或 Qwen3-ASR 代码。
